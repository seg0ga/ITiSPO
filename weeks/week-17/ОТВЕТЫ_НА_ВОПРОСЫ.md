# Вопросы для самопроверки

1. **Какие критерии вы использовали при разделении монолита на микросервисы (или при проектировании сервисов)?**

    Я разделил систему по ролям: gateway принимает внешние запросы, logs-svc-s05 работает с логами, log-notifier получает внутренние gRPC-уведомления
2. **Почему вы выбрали именно этот стек технологий (язык, БД, протоколы)?**

    Я выбрал Python и FastAPI, потому что этот стек хорошо подходит для restapi и быстро собирается в контейнеры. Для связи между сервисами используется http для внешнего api и grpc для внутреннего
3. **Как ваши сервисы справляются с ошибками (retry, circuit breaker, graceful degradation)?**

    Есть простой retry при вызове notifier'а. Если он недоступен, то logs-service просто продолжает работать (graceful degradation)
4. **Как организован деплой и обновление вашей системы без простоя (Zero Downtime)?**

    Деплой и обновление системы сделаны через kubernates. (условно, в теории, тк требовалось только опистаь) при обновлении сначала запускается новая версия, а только потом выключается старая
5. **Что было самым сложным в интеграции всех компонентов вместе?**

    Самым сложным было связать REST, gRPC, Docker и Kubernates в одном проекте так, чтобы все работало и не выдавало ошибки
6. **Что бы вы улучшили, если бы у вас был еще месяц?**

    Расширил бы функционал: добавил полноценную базу данных, улучшил обработку ошибок.
